## Firmware boundaries and invariants

- **2026-10-20 implementation supersedes the earlier documentation-only review.** Corrected `GameLevel` Cyclon/Sorrend profiles and new Kapcsolozar/Parbaj games are implemented in handwritten source. The generator still ignores `GameLevel`; do not claim automatic import. See [implemented rules](docs/EXCEL_CONFIG_ARCHITECTURE.md#implemented-gamelevel-rules-2026-10-20). Keep the user-owned handoff unchanged.
- Keep [src/main.cpp](src/main.cpp) as a thin Arduino entry point, including Arduino.h before defining `setup()` and `loop()`.
- Keep portable state machines separate from Arduino hardware adapters. Add host regression tests for changed state, timing, bounds and cancellation behavior.
- Keep the two permanent cooperative application tasks; never schedule another recurring task per menu selection, button press or result. Do not add blocking waits or Arduino `String` allocation to runtime paths. Use unsigned elapsed-time subtraction for timer rollover.
- Preserve **Szint1..Szint5**, **Ujrainditas**, **Debug**. Szint1: Random, Random 2 (IDs35/38); Szint2: Cyclon, Sorrend, Sima villogo (IDs10/36/37; ASCII LCD label, mode `Flasher`). Szint3: Cyclon42, Sorrend39, Kapcsolozar45, Parbaj47; Szint4: Cyclon43, Sorrend40, Kapcsolozar46; Szint5: Cyclon44, Sorrend41; each level has Back. Former Simon mondja is now Sorrend; internal `Simon` / `playSimon` names stay. New action callbacks are defined in [src/ui/MenuCallbacks.cpp](src/ui/MenuCallbacks.cpp). - Use [src/config/PinConfig.h](src/config/PinConfig.h), [src/config/BoardConfig.h](src/config/BoardConfig.h), [src/config/NavigationConfig.h](src/config/NavigationConfig.h), [src/config/LedConfig.h](src/config/LedConfig.h) and [src/config/PanelConfig.h](src/config/PanelConfig.h) as configuration authorities. Do not silently change wiring or the workbook.
- Keep the workbook-selected strip data pin (currently D4) under one FastLED controller with a 100-pixel buffer. Cyclon uses 75 pixels and clears the tail; panel games use workbook-mapped pixels through 86 and require at least 86 physical pixels for all lamps. Strip-test exit and game cancellation clear all 100 pixels. Ikarus inputs/LED outputs remain separate; Random accepts safe configured contacts including Cyclon/Ikarus but never automatically lights the matching Ikarus lamp.
- Boot with no selected game and a dark strip. Selecting Cyclon waits for fresh D39. Its four internal stage intervals/widths by menu level are 2: 50/40/40/40 ms, 9/5/5/3 LEDs; 3: 40/35/30/30, 9/5/5/3; 4: 50/40/35/20, 5/3/2/2; 5: 40/35/30/20, 5/3/2/1. Two-pixel windows mean centre and centre+1 only. Random accepts safe configured digital contacts, not menu/peripherals: one random panel lamp/hue and 220–1760 Hz tone for 250 ms per fresh debounced press. Reselection resets games.
- Flasher uses the same 11 inputs and corrected mapping as Simon, consuming a fresh any-button start and requiring release after playback. Preserve 500 ms initial pause, 500 ms target light, 200 ms dark, then the same target reappears and remains visible awaiting its matching button (nonmemory). Correct input gives 540 ms green/same Win chime, then chooses a new single target. Unlimited rounds: never accumulate a sequence or stop at 32. Wrong input/chord/10-second input inactivity gives 740 ms red/same Loss, then Ready for a fresh start. Re-selection resets; do not apply Sorrend's new memory profiles to Flasher.
- Sorrend at every menu level 2–5 is growing 1–32 **memory** play with white targets. Level2: no distractors/deadline; level3: 4–6 distractors/3000 ms per answer/warnings at 2/1 seconds remaining; level4: 4–10/2000 ms/1/0.5 seconds; level5: 8–10/1200 ms/1/0.5 seconds. Distractors are distinct saturated-colored non-target channels, refreshed per shown step and visible only in Showing (explicit implementation choice; workbook unspecified). Input hides target and distractors. Preserve fresh any-panel start, 500 ms intro/show, 200 ms gaps, playback-release gating, 540 ms green/Win per correct answer, 740 ms red/Loss for wrong/chord/deadline; deadline wins at boundary. Each Input entry resets its per-answer timer; max32/failure returns Ready. Warning is 80 ms/880 Hz. Reselection resets.
- [src/game/ChallengeGames.cpp](src/game/ChallengeGames.cpp) is portable. Kapcsolozar3/4 reads literal HIGH bits SW01–05 = D40/42/38/36/37, paired strip76–80. Level3 lit→HIGH/off→LOW, unlimited; level4 inverse, 2-second deadline wins, warnings1/0.5 seconds remaining. Selection starts immediately with a random displayed mask excluding the already-solved vector; all five required levels must be stable together for 30 ms. Win540/Loss740 then Ready; fresh D39 starts another round. Physical HIGH=up is an assumption requiring hardware verification.
- Parbaj (Szint3): upper channels0–2 left,8–10 right; three distinct colors each, exactly one shared from five palette hues. Auto-start selection/reselection; 2-second preview with warnings1/0.5 seconds remaining, then bottom-middle BTN09/channel5/pixel73 shows common color while upper colors remain. No response deadline; preview-held inputs require release. Correct wins/wrong loses; same-side chord is wrong. Simultaneous both-correct→both green/draw; both-wrong→both red/draw; mixed→correct side wins. Three 90 ms on/off blinks (540 ms), one Win/Loss sound; Ready needs fresh upper press for another round.
- Random 2 accepts Random's safe contacts but lights their own workbook-paired lamps (including six Ikarus GPIO lamps and metal switch pixels76–80), preserving the lower-row correction. Unpaired inputs still trigger the effect. Fresh/chord presses start/replace a 1200 ms effect: eight 150 ms beats, tiny original Playful tune (32-byte flash table), three random strip pixels1–70. Held/bouncing/selection-held buttons do not repeat; completion goes dark but stays selected. PairedLampOutputs/GameLamps borrow only free polarity-defined GPIO lamps, restore prior input/pull-ups on cancellation, and leave changed/existing output owners alone. Back, another game, Debug and restart stop sound, release lamps inactive and clear all100 pixels. Original Random never drives matching Ikarus lamps.
- Selecting any game disables tcMenu automatic return entirely via `renderer.turnOffResetLogic()` through Ready/gameplay/results. Manual Back/root, leaving the owning level, another game/menu, Debug or restart cancels the old game/audio and clears all100 strip pixels; manual cancellation restores normal 120-second menu/Debug timeout, while a newly selected game disables it again. Flasher's 10-second timeout, Sorrend3/4/5 per-answer deadlines, Kapcsolozar4 deadline and LED Debug's own120-second timer are independent. No automatic resume after Debug. New games reuse the existing two tasks and one strip buffer.
- Export numeric column B (`Info`) in `PinMap_export` and `LampPairs` unchanged. User reported the lower row appeared reversed: PanelConfig corrects only its lamp-channel association, giving BTN07–11 → 75/74/73/72/71; inputs stay in BTN order. Upper groups stay BTN01–03 → 84/85/86 and BTN12–14 → 83/82/81. Do not remove this physical correction by blindly restoring workbook pair order. Generated `PinDefinition::stripPixel` is 1-based, 0 unspecified; skip descriptive/range text and validate numeric pixels as unique 1–100.
- Keep joystick navigation single-step, fixed-repeat and neutral-rearmed. tcMenu owns the absolute encoder position; do not restore its old accelerated joystick task or introduce a second cursor.
- Button tests may temporarily enable pull-ups only on eligible INPUT pins. Preserve reserved pins, A9 navigation, existing pull-ups and output owners. Restore only the test's own changes on Back, mode change and timeout.
- Keep menu metadata and [Gyerek_jatek_arduinomega.emf](Gyerek_jatek_arduinomega.emf) synchronized, with stable runtime-list sizes and non-overlapping ID ranges. Preserve the project-owned safe renderer and input bindings after designer regeneration; do not edit installed libraries or generated build caches.

## Validation and handoff

- Prefer implementing and building firmware before generating new regression tests when that gives a smaller, cheaper feedback cycle; then add focused tests and run the full suite. Keep tool output and explanations concise to reduce token use (user preference, 2026-10-15).
- For firmware/menu changes, use the VS Code tasks **Build Gyerek_jatek (Mega)** and **Test Gyerek_jatek (no hardware)**. Equivalent commands are `platformio run -e megaatmega2560` and `python tools/run_tests.py`; the native runner also accepts `--sanitize` when supported.
- Preserve strict project warnings and the documented unused-parameter exception for upstream inline headers. Read full build errors before changing flags or dependencies.
- Do not upload firmware, stage/commit changes or modify unrelated workbooks/backups unless requested. Report what was actually built, tested and uploaded.
- Hardware acceptance is separate from native tests. Use [docs/HARDWARE_TEST_CHECKLIST.md](docs/HARDWARE_TEST_CHECKLIST.md); distinguish user-reported tests from tests performed in the current session.
- When behavior changes, update the technical README, Hungarian [HASZNALATI_UTMUTATO.md](HASZNALATI_UTMUTATO.md), relevant tests and hardware checklist.
