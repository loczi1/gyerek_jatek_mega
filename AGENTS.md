# Project guidance for future coding sessions

## Start here

- Read [docs/SESSION_HANDOFF.md](docs/SESSION_HANDOFF.md) for the latest checkpoint, then [README.md](README.md) for architecture and wiring. The current source and Git diff take precedence over dated notes.
- Work in [Gyerek_jatek.code-workspace](Gyerek_jatek.code-workspace), which contains only this project. Inspect Git status before editing; preserve existing staged, unstaged and untracked work.
- Target Arduino Mega 2560, AVR C++11 and the pinned PlatformIO environment `megaatmega2560`. Do not introduce a new framework, RTOS or dependency upgrade without a requirement.

## Firmware boundaries and invariants

- Keep [src/main.cpp](src/main.cpp) as a thin Arduino entry point, including Arduino.h before defining `setup()` and `loop()`.
- Keep portable state machines separate from Arduino hardware adapters. Add host regression tests for changed state, timing, bounds and cancellation behavior.
- Keep the two permanent cooperative application tasks; never schedule another recurring task per menu selection, button press or result. Do not add blocking waits or Arduino `String` allocation to runtime paths. Use unsigned elapsed-time subtraction for timer rollover.
- The user-requested redesign supersedes the old three-option root: preserve **Szint1..Szint5**, **Ujrainditas**, **Debug**. Szint1 contains **Random**, then **Random 2** (ID38); Szint2 contains **Cyclon**, **Simon mondja**, then **Sima villogo** (ASCII LCD label; Hungarian prose: Sima villogó; mode `Flasher`). Szint3–5 are intentionally Back-only, reserved by user request. Standalone melody/player modules are not active firmware features; Random 2 uses a tiny SoundEffects pattern instead.
- Use [src/config/PinConfig.h](src/config/PinConfig.h), [src/config/BoardConfig.h](src/config/BoardConfig.h), [src/config/NavigationConfig.h](src/config/NavigationConfig.h), [src/config/LedConfig.h](src/config/LedConfig.h) and [src/config/PanelConfig.h](src/config/PanelConfig.h) as configuration authorities. Do not silently change wiring or the workbook.
- Keep the workbook-selected strip data pin (currently D4) under one FastLED controller with a 100-pixel buffer. Cyclon uses 75 pixels and clears the tail; panel games use workbook-mapped pixels through 86 and require at least 86 physical pixels for all lamps. Strip-test exit and game cancellation clear all 100 pixels. Ikarus inputs/LED outputs remain separate; Random accepts safe configured contacts including Cyclon/Ikarus but never automatically lights the matching Ikarus lamp.
- Boot with no selected game and a dark strip. Selecting Cyclon waits for fresh D39; Random, Simon and Flasher re-selection reset them. Simon consumes a fresh start press from any of its 11 buttons and requires release after playback. Preserve its growing 1–32 sequence, 500 ms initial pause/light and 200 ms gap, 540 ms green/Win feedback, 740 ms red/Loss feedback, chord rejection and 10-second input timeout; completion/failure returns to Ready for a fresh press. Random accepts every safe configured digital input/switch contact, not menu/peripherals: one random panel lamp/hue and 220–1760 Hz tone for 250 ms per fresh debounced press.
- Flasher uses the same 11 inputs and corrected mapping as Simon, consuming a fresh any-button start and requiring release after playback. Preserve 500 ms initial pause, 500 ms target light, 200 ms dark, then the same target reappears and remains visible awaiting its matching button (nonmemory). Correct input gives 540 ms green/same Win chime, then chooses a new single target. Unlimited rounds: never accumulate a sequence or stop at 32. Wrong input/chord/10-second input inactivity gives 740 ms red/same Loss, then Ready for a fresh start. Re-selection resets; existing Simon behavior is unchanged.
- Random 2 accepts Random's safe contacts but lights their own workbook-paired lamps (including six Ikarus GPIO lamps and metal switch pixels76–80), preserving the lower-row correction. Unpaired inputs still trigger the effect. Fresh/chord presses start/replace a 1200 ms effect: eight 150 ms beats, tiny original Playful tune (32-byte flash table), three random strip pixels1–70. Held/bouncing/selection-held buttons do not repeat; completion goes dark but stays selected. PairedLampOutputs/GameLamps borrow only free polarity-defined GPIO lamps, restore prior input/pull-ups on cancellation, and leave changed/existing output owners alone. Back, another game, Debug and restart stop sound, release lamps inactive and clear all100 pixels. Original Random never drives matching Ikarus lamps.
- Selecting any game (Cyclon, Random, Random 2, Simon or Flasher) disables tcMenu automatic return entirely via `renderer.turnOffResetLogic()`. Preserve this through ready, gameplay and results, including after completion/failure: the game remains selected with no menu timeout. Manual Back/root, leaving the owning level, another menu, Debug or restart cancels game, tone and all 100 strip pixels and restores the normal 120-second menu/Debug timeout. Simon's and Flasher's 10-second input inactivity timeouts and the LED Debug screen's own 120-second timer are independent. No automatic resume after Debug; select a game again. Keep Cyclon's four internal difficulties distinct from root levels.
- Export numeric column B (`Info`) in `PinMap_export` and `LampPairs` unchanged. User reported the lower row appeared reversed: PanelConfig corrects only its lamp-channel association, giving BTN07–11 → 75/74/73/72/71; inputs stay in BTN order. Upper groups stay BTN01–03 → 84/85/86 and BTN12–14 → 83/82/81. Do not remove this physical correction by blindly restoring workbook pair order. Generated `PinDefinition::stripPixel` is 1-based, 0 unspecified; skip descriptive/range text and validate numeric pixels as unique 1–100.
- Keep joystick navigation single-step, fixed-repeat and neutral-rearmed. tcMenu owns the absolute encoder position; do not restore its old accelerated joystick task or introduce a second cursor.
- Button tests may temporarily enable pull-ups only on eligible INPUT pins. Preserve reserved pins, A9 navigation, existing pull-ups and output owners. Restore only the test's own changes on Back, mode change and timeout.
- Keep menu metadata and [Gyerek_jatek_arduinomega.emf](Gyerek_jatek_arduinomega.emf) synchronized, with stable runtime-list sizes and non-overlapping ID ranges. Preserve the project-owned safe renderer and input bindings after designer regeneration; do not edit installed libraries or generated build caches.

## Validation and handoff

- Prefer implementing and building firmware before generating new regression tests when that gives a smaller, cheaper feedback cycle; then add focused tests and run the full suite. Keep tool output and explanations concise to reduce token use (user preference, 2026-10-15).
- For firmware/menu changes, use the VS Code tasks **Build Gyerek_jatek (Mega)** and **Test Gyerek_jatek (no hardware)**. Equivalent commands are `platformio run -e megaatmega2560` and `python tools/run_tests.py`; the native runner also accepts `--sanitize` when supported.
- Preserve strict project warnings and the documented unused-parameter exception for upstream inline headers. Read full build errors before changing flags or dependencies.
- Do not upload firmware, stage/commit changes or modify unrelated workbooks/backups unless requested. Report what was actually built, tested and uploaded.
- Hardware acceptance is separate from native tests. Use [docs/HARDWARE_TEST_CHECKLIST.md](docs/HARDWARE_TEST_CHECKLIST.md); distinguish user-reported tests from tests performed in the current session.
- When behavior changes, update the technical README, the Hungarian [HASZNALATI_UTMUTATO.md](HASZNALATI_UTMUTATO.md), relevant tests and normally the dated handoff.
